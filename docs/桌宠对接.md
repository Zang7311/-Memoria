# 桌宠对接（应用 → 桌宠联动）

> 2026-10-31 落地。桌宠 `pet-native` 是独立进程（Win32 分层窗口 + Live2D），不经过 WebView，
> 所以用不了 Tauri 的事件/IPC；应用和它之间靠一条**本机 UDP 单向通道**说话。

## 一句话流程

铃在聊天里回完一句话 → 应用把它（和猜出来的情绪）打到 `127.0.0.1:46180` → 桌宠收到就在头顶冒气泡。

## 协议

一个数据报一帧，UTF-8，四个字段用制表符 `\t` 分隔：

```
v1<TAB>happy<TAB>6.0<TAB>主人大人继续说，铃的小耳朵竖着呢
```

| 字段 | 说明 |
|---|---|
| `v1` | 版本号，不认识就丢弃 |
| mood | `calm` / `happy` / `sad` / `angry` / `curious`，只影响气泡底色 |
| ttl | 气泡停留秒数（浮点） |
| 正文 | 一行文本；应用侧先压到 **24 字 + 省略号**，桌宠侧再兜底截 30 字 |

## 代码位置

| 位置 | 干什么 |
|---|---|
| `src-tauri/src/desktop/pet_talk.rs` | 情绪关键词判断、压行截断、发包、`native_pet_say` 命令（含 3 条单测） |
| `src/composables/useStreamRender.ts` | 铃回话结束时取这条消息的正文，调 `nativePetSay` |
| `src/components/settings/PersonaSettings.vue` | 「形象 → 桌面伙伴」里的「回话时头顶冒气泡」开关 |
| `pet-native/src/main.rs` | `spawn_talk_listener` 收包 → `PostMessage(WM_APP_PET_SAY)` → 主线程冒气泡 |

## 情绪怎么来的

没有接模型打标，只是关键词粗判（`pet_talk::mood_of`）：
难过/道歉类 → sad，生气类 → angry，开心/感叹/道谢 → happy，问句 → curious，其余 calm。
负面前置判断，宁可平淡也不要误判成开心。

## 开关与容错

- 设置里关掉「回话时头顶冒气泡」后，后端直接返回、不发包。
- 桌宠没启动 / 端口被占 / 什么都没监听：UDP 发送不会报错，日志里只有一条 debug，前端不会弹提示。
- 桌宠那侧绑定 46180 失败只打一行日志，桌宠本体照常工作（只是不再显示聊天气泡）。

## 怎么手工验证

```powershell
# 1) 起一只桌宠（如果应用没在跑）
Start-Process 'F:\项目\ling-mem\pet-native\target\release\pet-native.exe'

# 2) 直接发一帧（模拟应用）
$u = New-Object System.Net.Sockets.UdpClient
$bytes = [Text.Encoding]::UTF8.GetBytes("v1`thappy`t8`t这是一条测试气泡")
[void]$u.Send($bytes, $bytes.Length, '127.0.0.1', 46180); $u.Close()
```

气泡应立刻出现在桌宠头顶；三行以内、超长会截断成省略号。

## 桌宠形态是「三选一」

设置 → 形象 → 桌宠：

| 形态 | 是什么 | 实现 |
|---|---|---|
| Live2D 桌宠 | 独立小窗、全身形象，能拖动/摸头/掉到屏幕底 | `pet-native.exe`（独立进程） |
| 圆球桌宠 | 应用内的圆形小窗，可选头像或纯文字、大小、透明度 | `floating-ball` 窗口（WebView） |
| 不显示 | 两种都不跑，气泡联动一起停 | 两个开关都关 |

界面上的选中状态由两个配置开关推导（`native_pet_enabled` 优先），切换时互斥写回，
并立即：启停桌宠进程（`native_pet_sync`）、显示/隐藏圆球窗口（`set_floating_ball_visibility`）。
两个形态不会同时出现，圆球的「样子」里也不再提供 Live2D（那是另一种形态，不是圆球的样子）。
