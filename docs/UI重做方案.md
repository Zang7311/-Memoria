## 一、现状诊断：为什么看起来「处处不满意」

有据可查的四条，不是感觉：

| 问题 | 证据 |
|---|---|
| 没有唯一的设计令牌 | `--var` 定义散落在 15 个文件里共 114 处，只有 `src/App.vue` 有一个 `:root`，各组件各写一份覆盖 |
| 同一位置混用两套图标体系 | 顶栏同时有 emoji（🟢🔴🪶🔄✅）和 SVG 图标（记忆/插件/工具箱）和纯文字按钮（执行记录/目标） |
| 顶栏承担了全部导航 | 主窗口顶部一横排塞了 9 个入口 + 一个 `<select>` 人格选择器，没有分组 |
| 面板没有统一外壳 | MemoryPanel / GoalsPanel / ToolboxPanel / PluginManager / AuditPanel 各自写一套标题栏、内边距、关闭按钮 |

结论：不是某个页面难看，是**没有骨架、没有令牌**，两个 AI 各自发挥。所以这次先定骨架和令牌，
再让页面往里填。

## 二、三套骨架（预览见 ui-mockup.html）

| | A 三栏（DeepSeek 风） | B 单列（Twitter 风） | C 窄图标栏 + 抽屉 |
|---|---|---|---|
| 结构 | 左 260 会话列表 + 中对话 + 右 320 面板 | 顶部胶囊导航 + 中 680 单列 | 左 60 图标栏 + 中对话 + 右侧可收起抽屉 |
| 1200 宽下中栏可用 | 620 px（偏窄） | 680 px（两侧留白约 360 浪费） | **840~1140 px** |
| 历史会话是否常驻 | 常驻，一眼可见 | 不常驻 | 不常驻（抽屉里，点图标滑出） |
| 适合场景 | 会话多、像 AI 网页端 | 社区/信息流 | 常驻陪伴、窗口宽高比紧 |

**我的裁决：用 C 做骨架，吸收 A 的会话列表。**
理由：主窗口固定 1200×720，A 的右侧面板常态占 320 太浪费；B 的两侧留白在桌面应用里没有意义。
C 的中栏能到 840 以上，聊天读起来最舒服。会话列表放进抽屉第一页，点左上角图标**覆盖式滑出 260 宽**，
不挤压中栏（Linear / Notion 的做法）。

## 三、设计令牌（全应用唯一来源）

写进 `src/styles/tokens.css`，`:root` 一份，`html.light` 只覆盖颜色。
**任何组件不允许自己定义颜色/字号/圆角字面值。**

### 颜色（暗色为默认）

| 变量 | 暗色 | 亮色 | 用途 |
|---|---|---|---|
| `--bg` | `#0F1116` | `#FFFFFF` | 窗口底 |
| `--bg-panel` | `#14161D` | `#FAFAFB` | 侧栏/抽屉/顶栏 |
| `--bg-raised` | `#1A1D26` | `#FFFFFF` | 卡片、输入框 |
| `--bg-hover` | `#1F232E` | `#F2F3F5` | 悬停/选中底 |
| `--border` | `#242833` | `#E7E8EC` | 分隔线 |
| `--border-strong` | `#333847` | `#D6D8DE` | 输入框、需要强调的边 |
| `--text` | `#E9EBEF` | `#17181C` | 正文 |
| `--text-2` | `#A0A6B4` | `#5B616E` | 次要文字 |
| `--text-3` | `#6E7686` | `#8C93A1` | 提示、时间戳 |
| `--accent` | `#FF7A94` | 同 | **只用于主按钮、选中态、铃的身份色** |
| `--ok/warn/err` | `#3FB950` / `#D29922` / `#F85149` | 同 | 状态点、错误文字 |

主色仍是粉色（铃的身份色），但**中性色占 95%**，杜绝「满屏彩色 AI 味」。

### 尺度

| 类别 | 允许值 |
|---|---|
| 字号 | 11 / 12 / 13 / 14 / 16 / 20（**只有这 6 档**，一屏内不超过 4 档） |
| 行高 | 正文 1.6，标题 1.3 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24（4 的倍数，禁止 5px、18px 这类） |
| 圆角 | 6（小件）/ 10（卡片、输入框）/ 14（气泡）/ 99（胶囊） |
| 阴影 | 只有一层 `--shadow`，用于输入框、抽屉、弹窗 |
| 边框 | 1px，只用 `--border` 或 `--border-strong` |
| 动效 | 120ms（悬停）/ 180ms（面板滑入），`ease-out`，不做弹跳 |

## 四、组件契约（重写时按这个来，不一致就打回）

| 组件 | 规则 |
|---|---|
| `AppButton` | 三档：`primary`（粉底，一屏最多 1 个）/ `ghost`（1px 边框）/ `text`（无底无边）。高度统一 30px |
| `AppInput` / `AppTextarea` | 底 `--bg-raised`，边 `--border-strong`，圆角 10，聚焦时边变 `--accent`（不发光） |

| `AppPanel` | 所有侧面板共用外壳：52px 标题栏（标题 + 关闭按钮）+ 内容区，自己不许再写标题栏 |
| `AppTabs` | 胶囊组，选中用 `--bg-hover`，不用下划线也不用彩色条 |
| `AppStatusDot` | 6px 圆点 + 文字，替代 🟢🔴⚪ |

### 踩坑记录：`overflow: hidden` 不是「不可滚动」

**现象**：设置页里点任意开关，面板还在、但里面的导航和内容整块消失，像被清空了，关掉重开才恢复。

**根因**：`overflow: hidden` 的元素**依然是可滚动容器**（只是没有滚动条，用户滚不了、脚本和浏览器能滚）。开关的隐藏 checkbox 拿到焦点后，浏览器为了「把焦点元素滚进可视区」，滚的正是最近的滚动祖先 —— 也就是设置面板本身（`scrollTop ≈ 919px`），于是面板内容被整体顶出可视区。

**修法**：
1. 隐藏 checkbox 由 `position: absolute` 改为 `position: fixed`，聚焦不再触发任何祖先滚动；
2. 主页布局、右侧抽屉、面板容器、设置面板的 `overflow: hidden` 改为 `overflow: clip`（`clip` 不产生滚动容器，物理上无法被滚）。

**验证方式（可复用）**：临时在页面上打印目标元素的 `getBoundingClientRect()`，点一次开关看 y 有没有变；修好后点开关前后 y 恒为 50。
