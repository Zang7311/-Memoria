# 执行记录

主界面顶部的「执行记录」可查看、展开和检索执行历史。支持类型、结果、今天／7天／全部筛选；关键词匹配标题、工具名、文件路径、工具简报和结果摘要。「导出 JSON」下载当前筛选结果。「清空全部记录」必须先点击按钮，再确认中文不可恢复提示；不会清理会话、记忆、目标、配置或实际工作文件。

## 存储和保留

- 默认目录：用户目录下的 .铃记忆体；活动文件为 audit.jsonl。
- 每条执行完成后仅追加一行 JSON；取消或超时也会尽力记录。不会重写、截断或整理已有 JSONL 文件。
- 活动文件超过 5 MiB 后立即重命名为递增编号的 audit-N.jsonl。为同时满足严格追加和精确保留条数，还在下一次追加前将上一条执行记录滚动为独立的不可变分段；正常情况下活动文件保存最新一条执行。每个分段仅有一条执行记录，最多 2000 个分段。
- 查询、检索和导出均包含归档文件，按执行记录写入顺序保留最新 2000 条，展示时最新在前。超出上限时直接删除最老分段，不隐藏过期前缀、不改写旧文件，磁盘上的有效记录数也严格受上限约束。代价是使用较多小文件；默认最多 2000 个。
- 可选 .铃记忆体/audit-config.json 配置，在应用启动后第一次使用审计存储时加载；修改后重启应用。省略字段采用默认值，0 归一为 1，配置格式无效时采用默认值：

~~~json
{"max_entries": 2000, "max_file_bytes": 5242880}
~~~

## 记录覆盖

| 类型 | 入口 | 记录方式 |
| --- | --- | --- |
| 对话 chat | send_message 后台生成 | 用户消息首行的脱敏标题、请求和会话、时间、结果、耗时；不复制回复 |
| 任务 agent | run_agent_loop | 从配置准备到执行结束；聚合全部实际工具调用，包括错误和拒绝 |
| 子任务 sub_agent | spawn_sub_agents 中的每个子执行 | 单独聚合，保留父请求 id；并行任务互不串记录，超时取消仍记录 |
| 目标 goal | advance_goal | 手动和自动推进共用入口；关联 goal_id 和本轮请求，记录步骤完成数变化和本轮工具 |
| 自造 forge | forge_from_args | 单独记录工具名、请求、试跑／注册是否成功；权限拒绝和注册失败同样记录 |

工具意图复用现有 x-intent，不改变路由或工具定义。普通 Agent 与子任务的改动路径来源于工具参数，包括工具箱实际使用的 input JSON／纯路径格式；写、删、移动、复制、下载、目录创建及压缩／解压均支持。移动记录源和目标，压缩／解压只记录输出路径。目录级操作记目标目录，不枚举压缩包内所有文件。只有成功返回的调用计入改动路径，失败调用保留工具明细但不宣称文件已变更。

## 隐私和失败隔离

不保存工具参数、命令原文、工具输出、文件内容、网页正文、模型最终回复、自造工具代码和人格设定。工具简报最长 100 字、标题最长 60 字、结果摘要最长 200 字。命令只记录已调用，不保存命令片段，避免命令行参数携带密钥。目标摘要只使用步骤计数，不复制模型产生的自由文本。

标题和元数据屏蔽配置中的 API 密钥、命名为密钥／密码的环境变量、常见凭据标记和长凭据串；调用中明确标注的密钥／密码也用于屏蔽标题和路径。含人格／角色设定标记的标题替换为占位文本。敏感或不安全的路径不记录。UI 使用文本插值，不渲染记录里的 HTML。

记录采用任务局部上下文，聚合并行工具并保留发起顺序。文件写入、归档、保留清理失败只在 app.log 写固定警告，不把错误向主任务返回，也不记录原始错误内容。读写和清空共用存储锁，防止行交错和清理竞态。前端拒绝过期搜索响应，清空期间不启动新的查询。

审计写入失败时该次记录可能缺失，这是不中断主流程的明确取舍。程序被强制终止或断电时，未完成的执行不能保证记录；损坏的 JSONL 行会跳过，后续写入滚动到新分段，不修补旧字节。查询、导出和清空使用后台阻塞任务，避免磁盘读取阻塞界面。没有改动人格、角色、主密码加密或现有经验记忆。
